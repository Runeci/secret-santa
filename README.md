# 🎅 Тайный Санта — Telegram-бот на Cloudflare Workers

TypeScript, [grammY](https://grammy.dev), Cloudflare Workers + D1 (SQLite) + Queues. Работает через
webhook, не засыпает, помещается в бесплатный тариф Cloudflare. Банковская карта не нужна.

> Рядом лежит `python-oracle/` — первая версия на Python/aiogram для обычного сервера (VPS).
> Для Cloudflare она не нужна.

## Иконка

`assets/icon.png` — оригинал. Для аватарки бота: `assets/avatar-640.png` (квадрат 640×640, углы залиты

## Развёртывание (около 15 минут)

Понадобятся: аккаунт Cloudflare, Node.js 20+ и токен от @BotFather.

```bash
npm install
npx wrangler login
```

1. **База данных.** Создайте её и вставьте выданный `database_id` в `wrangler.toml`:
   ```bash
   npx wrangler d1 create secret-santa
   ```
2. **Очередь** (для рассылки пар после жеребьёвки):
   ```bash
   npx wrangler queues create santa-outbox
   ```
3. **Таблицы:**
   ```bash
   npx wrangler d1 migrations apply secret-santa --remote
   ```
4. **Деплой.** В конце команда напечатает адрес вида `https://secret-santa-bot.<поддомен>.workers.dev`:
   ```bash
   npx wrangler deploy
   ```
5. **Секреты.** Токен бота и случайная строка для защиты webhook (команда спросит значение):
   ```bash
   npx wrangler secret put BOT_TOKEN
   ```
   ```bash
   openssl rand -hex 16
   ```
   ```bash
   npx wrangler secret put WEBHOOK_SECRET
   ```
   (во второй команде вставьте строку, которую вывела `openssl`; запомните её — она нужна в шаге 6)
6. **Подключить Telegram к Worker** (значения подставьте свои):
   ```bash
   BOT_TOKEN=... WEBHOOK_SECRET=... WORKER_URL=https://secret-santa-bot.<поддомен>.workers.dev bash scripts/set-webhook.sh
   ```
   В ответе должно быть `"ok":true` и ваш адрес в `getWebhookInfo`.
7. Откройте бота в Telegram и отправьте `/start`.

Обновление после изменений: `git pull`, затем `npx wrangler deploy`. Логи: `npx wrangler tail`.

Организатор может удалить игру кнопкой «🗑 Удалить игру» в «Управлении игрой» (до и после жеребьёвки):
участники получают уведомление, все данные игры стираются.

## Автодеплой

Worker подключён к GitHub через Workers Builds: каждый пуск в ветку `main` запускает
`npm ci && npm test`, и только если тесты прошли, выполняется `npx wrangler deploy`.
Настройки: Cloudflare Dashboard → Workers & Pages → `secret-santa-bot` → Settings → Builds.
Секреты и webhook при выкладке не меняются. **Миграции применяются вручную и ДО выкладки кода**, который их использует:
`npx wrangler d1 migrations apply secret-santa --remote`, и только потом пуш в `main`.
Текущие: `0001_init.sql`, `0002_ready.sql` (отметка готовности списка), `0003_wish_link_price.sql` (ссылка и стоимость подарка), `0004_deadline.sql` (дедлайн игры).
В Cloudflare Deploy command = `npx wrangler d1 migrations apply secret-santa --remote && npx wrangler deploy`, так что миграции применяются сами.

## Устройство

| Файл | Назначение |
|---|---|
| `src/draw.ts` | жеребьёвка (чистая функция) |
| `src/db.ts` | запросы к D1 |
| `src/service.ts` | правила игры, права организатора/участника, лимиты |
| `src/bot.ts` | экраны, кнопки, диалоги |
| `src/outbox.ts` | рассылка личных сообщений через очередь |
| `src/index.ts` | точка входа Worker: webhook и потребитель очереди |
| `migrations/` | схема базы |

**Состояние диалога** (ввод названия, подарка, выбор группы для правила) хранится в таблице `user_state`:
Worker не помнит ничего между запросами.

**Рассылка пар.** На бесплатном тарифе Worker делает не больше 50 внешних запросов за вызов, а на
50 участников нужно 50 личных сообщений. Поэтому пары кладутся в очередь Cloudflare, а потребитель
отправляет их пачками по 10, с повтором при лимитах Telegram. Если кому-то доставить не удалось
(заблокировал бота), организатор получает предупреждение без раскрытия пар, а сам человек может
нажать «🎯 Кому я дарю».

**Жеребьёвка.** Сначала точная проверка, что решение существует. Потом поиск с возвратом с бюджетом
взаимных пар 0, 1, 2… — они появляются, только если иначе никак. Поиск ограничен по шагам из-за
лимита 10 мс процессорного времени на бесплатном тарифе.

**Правила жеребьёвки.** Минимум 3 участника; каждый участник добавляет хотя бы один подарок и нажимает
«✅ Мой список готов» (организатору показывается, у кого сколько подарков и кто ещё не готов); пары не пересекаются с правилами «кто кому не дарит».

**Подарок** = название (до 2000 символов) + необязательные ссылка (проверяется: http/https, настоящий домен, до 1500 символов)
и стоимость (короткий текст с цифрами). Санта получает всё целиком.

**Приглашение** уходит отдельным нейтральным сообщением, которое можно переслать как есть (организатор и участник).

**Дедлайн.** Организатор ставит дату и свой часовой пояс («Управление игрой» → «📅 Дедлайн»); дата видна всем в
меню игры, участники получают уведомление. Раз в час запускается расписание (cron в `wrangler.toml`): утром (10:00 по
поясу организатора) тем, чей список не готов, приходит напоминание **по субботам до дедлайна и за день до него**;
организатору — сводка за день до дедлайна и в его день. Не чаще раза в сутки, после жеребьёвки напоминаний нет.
Логика «кому и когда» — чистая функция `planReminders` (`src/reminders.ts`), покрыта тестами на границы суток и поясов.

**Только личные сообщения.** В групповых чатах бот ничего не показывает, чтобы пары не раскрылись.

**Надёжность.** Ошибка в обработчике не роняет webhook (иначе Telegram повторял бы действие), а
рассылка пар делится на пачки под лимит очереди (100 сообщений / 256 КБ); вступление и сохранение
жеребьёвки атомарны, поэтому гонка «вступил в момент жеребьёвки» не оставляет участника без пары.

**Лимиты** (`src/config.ts`): 20 пунктов, до 2000 символов в пункте (длинные списки Санте приходят несколькими сообщениями), минимум 3 участника, максимум 50 участников и 30 правил.

**Приватность.** Пары хранятся в таблице `assignments`; интерфейс показывает каждому только его
собственную пару, включая организатора. Владелец аккаунта Cloudflare технически может прочитать базу.
